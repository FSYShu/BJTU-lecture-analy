# 交大课录智析 · 需求分析和产品设计文档

# 项目背景与业务问题

## 项目背景

北京交通大学现有课程平台提供课程回放资源，课程回放是学生课后复习、缺课补学、考前巩固的重要学习资料。单节课程回放时长普遍在60‑120分钟，但原生回放工具能力有限，仅提供基础视频播放功能，缺少智能化学习辅助能力。学生直接观看完整回放的学习成本高、复习效率低下，大量宝贵的录课视频资源没有被充分利用。

## 业务问题与用户痛点

1. 时长久，重点难定位：单节回放60‑120分钟，学生复习需要反复拖动进度条，很难快速定位核心知识点，完整看完耗时巨大。

2. 语速不均，易漏关键：教师讲课节奏不统一，部分重点内容讲解较快，学生稍不留神就错过关键概念，需要反复回退重看。

3. 无配套字幕，信息获取弱：原生回放缺少字幕，教师口音、环境噪音、专业术语缩写，会干扰听课理解，只能反复重听确认内容。

4. 知识点碎片化，难以形成知识体系：课程视频内容是流式碎片化输出，观看结束后学生需要手动整理笔记，很难自动梳理完整知识脉络，考前复习缺少结构化知识框架。

# 用户角色与需求

## 用户角色定义

### 学生（核心用户）

**定义：**高校在校生，是系统的核心使用者与最终受益者。

**核心诉求：**快速定位课程重点、获取结构化的知识体系，将长视频回放的复习成本从“完整观看”压缩为“重点直达”，大幅提升复习效率。

**主要应用场景：**日常课后复习、考前集中冲刺、缺课后的快速补课。

**使用特征：**高频使用；对播放器、字幕、重点跳转、总结与思维导图的联动体验敏感，希望无需完整观看即可掌握课程要点。

### 教师/管理员（内容维护与运营角色）

**定义：**承担课程授权、专业术语维护、解析结果校审与异常处理的教师或平台管理员。

**核心诉求：**确保课程资源授权可控、术语准确、AI 生成内容可信、处理异常可发现可处理。

**主要应用场景：**课程授权与撤回、术语库维护、转写/重点/总结的人工校正（P1 起）、处理任务监控与失败干预。

### 课程平台（系统对接方）

**定义：**提供视频回放资源的校方平台（如北京交通大学课程平台），系统通过授权接口获取回放资源。

**核心诉求：**系统能够自动接入、批量拉取视频流，无需额外人工干预。

**主要应用场景：**后台静默完成视频解析与数据同步，支持 MP4、FLV、HLS 等主流回放格式。

# MVP范围与优先级

## MVP 成功标准

1. 系统能够从已授权的课程回放源取得视频，并完成音频提取和后台解析。

2. 系统能够生成带时间戳的中文转写、同步字幕、重点时间点、分层总结和基础思维导图。

3. 学生点击字幕、重点标记或思维导图节点后，播放器能够跳到对应位置。

4. 处理失败时，用户能够看到原因并重新发起任务，系统不会丢失原始课程记录。

5. 试点用户能够在规定时间内完成“找到指定知识点并开始播放”的任务。

## MVP 范围

### 核心业务链路

|**步骤**|**用户或系统动作**|**首版产出**|
|---|---|---|
|1|系统读取课程回放列表，或接收一条授权视频作为人工导入的备用方式。|待处理课程记录|
|2|后台下载视频、提取音频并进行降噪预处理。|可供识别的人声音频|
|3|ASR 服务生成带时间戳的转写文本和同步字幕。|转写与字幕文件|
|4|大模型按文本分段，生成重点、课程概览、章节要点和基础思维导图。|结构化解析结果|
|5|学生在播放器中查看结果，并通过重点、字幕或导图节点跳转。|可检索和可定位的回放体验|

### 范围内能力

- 课程回放列表读取、单条视频导入、视频地址解析、下载状态和失败重试。

- 音频提取、基础降噪、讯飞 ASR 调用、句级时间戳和字幕展示。

- 核心概念、定义、公式、例题和考点等重点类型的识别与时间点标注。

- 课程概览、章节要点、重点详解和复习提示等分层总结。

- 以课程主题为中心的两级思维导图，以及节点到视频时间点的跳转。

- 播放器、解析进度、结果缓存、基本权限和最小化运维页面。

### 范围外能力

- 直播课堂实时字幕、实时重点识别和课堂互动。

- 跨课程知识图谱、个性化推荐和自动规划学习路径。

- 自动评分、正式成绩联动和未经教师确认的考试题发布。

- 情绪、专注度、人脸或课堂行为识别。

- 完整原生移动应用、公开社区、弹幕和复杂社交功能。

- 首版即覆盖所有课程平台、所有流媒体协议和所有教务系统接口。

## 核心交互流程说明

核心链路为「获取回放 → 发起解析 → 查看结果 → 跳转回看」，覆盖 P0 全部场景。

1. **获取回放**：学生完成课程平台身份验证后进入系统，查看有权访问的课程回放列表，选择课程并点击「开始解析」。

2. **后台解析**：系统创建解析任务并展示处理状态，后台依次完成视频下载、音频提取、语音识别转写，并生成同步字幕、重点时间点、课程总结与思维导图；任务失败时明确提示原因并支持重试。

3. **查看结果**：解析完成后，学生进入课程详情页，在播放器、字幕、重点列表、课程总结、思维导图之间切换查看。

4. **跳转回看**：点击字幕文本、重点标记或思维导图节点，播放器跳转至对应时间位置，实现精准复习。

# 用户故事与验收标准

## US\-01：课程回放获取**（P0）**

**用户故事描述**

每次复习都要先进入学校课程平台寻找对应的回放视频，操作比较繁琐。我希望能够直接在系统中找到自己需要的课程回放，选择后即可开始解析，不必再手动下载和上传视频。

**验收标准**

|编号|验收标准|
|---|---|
|AC\-01\-01|学生完成课程平台身份验证后，系统能够获取并展示其有权访问的课程回放列表。|
|AC\-01\-02|课程回放列表正常加载后，学生能够查看课程名称及对应的回放信息，并选择需要解析的视频。|
|AC\-01\-03|学生选择某节课程回放后，系统能够获取该课程对应的视频资源信息，不需要学生手动下载并上传视频文件。|
|AC\-01\-04|学生选择课程回放并发起解析任务后，系统能够创建对应的解析任务，并开始获取视频资源。|
|AC\-01\-05|当课程回放资源无法获取时，系统应显示相应的错误提示，并将受影响的解析任务标记为失败，不得将其错误标记为解析成功。|

## US\-02：课程视频智能解析**（P0）**

**用户故事描述**

一节课程往往长达一两个小时，如果只是为了回顾某些知识点，重新观看整段视频会花费大量时间。希望系统能够自动识别教师的讲解内容，将视频中的语音转换为带有时间信息的文本，为后续快速查看和分析课程内容提供支持。

**验收标准**

|编号|验收标准|
|---|---|
|AC\-02\-01|系统成功获取课程视频后，能够自动提取视频中的音频内容，并启动语音识别任务。|
|AC\-02\-02|音频提取完成后，系统能够通过语音识别服务生成与课程讲解内容对应的转写文本。|
|AC\-02\-03|系统生成的转写文本应包含对应的时间戳信息，使文本片段能够关联至原视频中的相应位置。|
|AC\-02\-04|视频解析任务执行期间，系统能够显示相应的处理状态，使学生能够判断任务是否正在进行。|
|AC\-02\-05|视频解析成功后，系统能够保存对应的转写结果，并将其提供给后续课程内容分析模块使用。|
|AC\-02\-06|当音频提取、语音识别或视频解析过程中出现异常时，系统应显示任务失败状态，不得将未完成的解析结果标记为成功。|

## US\-03：课程重点时间点标注**（P0）**

**用户故事描述**
